## 3. Design decisions adopted

All locked Task 17 decisions were adopted (task §2):

- Product name **SilverLeaf Brief**, tagline *"What changed around
  SilverLeaf—and why it matters."*
- Framework-light static v0; primary nav Latest · Browse · About; secondary
  route Data & Sources; one reusable collection template for topic/place/entity.
- Home renders release order deterministically; no user-facing sort.
- Search prominent on Browse, compact on Home (Home ships a topic-shortcut
  rail, not a search hero).
- "Why it matters" visible on cards; trust label **Reviewed** with the exact
  detail definition; relevance and trust kept separate.
- Relevance labels: **In SilverLeaf / Near SilverLeaf / Countywide impact**
  (stable ids `in_silverleaf` / `near_silverleaf` / `countywide_impact`).
- Lifecycle rendered only when explicitly present; absolute labeled dates;
  no inferred staleness; no weekly-cadence promise; no historical filler.
- Non-goals respected: no dark mode, dashboard, map, account, alerting, API,
  semantic search, analytics, infinite scroll, confidence scores, etc.
- Implemented as a portable static app inside SJC_Intel (`site/`).

## 5. Implementation location and stack

**Location:** `site/` — a portable static application inside SJC_Intel,
relocatable to a future portfolio repository or deployable independently as
static assets (all URLs are relative; the site works at any path depth).

**Stack (justified):** semantic HTML + CSS + minimal vanilla JavaScript +
generated static pages + static JSON. A **Python generator**
(`scripts/build_static_site.py`) was chosen over a Node/JS framework because
the repository's entire tooling convention is deterministic Python scripts,
and route generation (30+ pages from one release) would otherwise be manual.
No Node, no database, no backend, no framework dependency; `browse.js` is the
only runtime JS and the core content is fully readable without it.

```
site/
  index.html                    (Latest, generated)
  browse/index.html             (Browse, generated)
  about/index.html              (About, generated)
  sources/index.html            (Data & Sources, generated)
  item/{id}/index.html          (generated)
  topic/{id}/  place/{id}/  entity/{id}/index.html   (one template, generated)
  404.html                      (generated)
  assets/css/silverleaf.css     (design system)
  assets/js/browse.js           (progressive enhancement)
  fixtures/demo/release.yaml    (demo fixture source)
  data/demo/                    (demo release artifacts, generated)
  data/releases/{id}/           (real release artifacts, generated)
  README.md                     (operator/build guide)
```

## 6. Static exporter

`scripts/build_static_release.py` completes §3B-G2:

- **Real mode** (`--release-id <id>`): validates the complete corpus first
  (blocks on errors), runs the deterministic publication selector, projects
  approved + reviewed + SilverLeaf-included items, validates content quality,
  and writes to `site/data/releases/{release-id}/`. Requires an explicit
  `--reviewer` (manifest only). May validly produce **zero selected items**
  (none are approved yet) — verified.
- **Demo mode** (`--demo`): reads the explicit fixture
  `site/fixtures/demo/release.yaml`, validates it, and writes to
  `site/data/demo/` with `environment: demo`.
- **`--check`** validates and reports without writing.
- **Required behaviors (task §5) all present:** reviewed-only selection via the
  selector; complete-corpus validation; public allowlist (only §2A fields,
  unknown keys rejected); internal denylist; deterministic release order
  (source date desc, then item id asc, undated last); stable
  topic/place/entity/source/relevance ids; source name + URL; absolute dates;
  lifecycle only when present; release counts; source-directory info
  (`dimensions.sources`); file checksums (sha256 in the manifest); schema/
  version identity; failure on incomplete required public fields; rollback
  identity (`prior_release_id`, `rollback_reference`); never marks anything
  published. `release.json` excludes `reviewer` (denylist §8); the manifest
  carries the release-level reviewer only.
- Byte-stable output verified (identical inputs → identical bytes).

## 7. Content-quality validation

`scripts/static_release_common.py::validate_public_item` enforces, per item:

- Required resident-facing copy: `public_item_id`, `title`, `summary`,
  `why_it_matters`, `source_name`, `source_date`, `published_date`, `relevance`
  (missing ⇒ error/exclude).
- At least one relevance/place relationship (relevance id required).
- Source URL XOR `source_unavailable` (invalid/absent URL without the flag ⇒
  error; broken links never remove a published item).
- Non-empty `topic_ids`; list types; stable public-ID shape.
- Public allowlist + internal denylist + no underscore-prefixed keys.
- Warnings (editorial, not exclusion): unexplained internal codes/acronyms in
  resident-facing copy (corpus item IDs, candidate IDs, planning codes),
  and missing conditional wording for proposed/under-construction items.

The exporter fails (or excludes) items lacking required content and never
manufactures missing values; warnings identify editorial-revision candidates.
Demo fixture passes with zero warnings.

## 11. Browse/search/filter behavior

- Search input always visible at top; begins after two characters; lexical
  only; deterministic; release order breaks ties; no sort menu; result count
  announced via `aria-live`.
- Filters: topic + relevance (visible), place + entity (secondary, collapsible);
  OR within a dimension, AND across dimensions; active-filter chips with
  remove; Clear all; zero-results state.
- Query parameters `q`, `topic`, `place`, `entity`, `scope` (scope = relevance);
  URL state shareable; browser Back restores state (popstate); Browse state
  preserved via URL + `sessionStorage` so item-detail back-links restore it.
- Progressive enhancement: the full list is server-rendered; `browse.js`
  filters/ranks/hides without re-rendering card markup. Verified in headless
  Chrome: `?topic=transportation` → 2 visible / 6 hidden, count "2 updates".
- Reference search logic lives in `scripts/site_search.py` (tested); the JS is
  a faithful port.
